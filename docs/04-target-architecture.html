Décision validée · IC-05

Une alpha à 0 USD sans enfermer le produit.

Idea Commons adopte un monolithe modulaire Next.js/TypeScript, PostgreSQL et une infrastructure gratuite à limites bloquantes. Les dépendances gérées sont entourées de formats et d'adaptateurs standards afin de préserver une sortie réaliste.

1. Contexte, objectif et non-objectifs

Contexte

Le produit doit protéger des projets privés, servir un catalogue public, rester utile sans IA et commencer avec un budget d'infrastructure fixe de 0 USD.

Objectif

Fixer une cible suffisamment précise pour construire le premier incrément, sans rendre un fournisseur indispensable au modèle métier.

Non-objectifs

  • Garantir une disponibilité de production avec des paliers gratuits.
  • Introduire des microservices ou une orchestration prématurée.
  • Choisir ici la stratégie IA, les prix ou le premier écran.

Principes

  • PostgreSQL reste le centre de gravité.
  • Les contrôles privés sont appliqués côté serveur.
  • Chaque service géré a une limite connue et une voie de sortie.
  • Aucun dépassement payant n'est activé automatiquement.

2. Décision et options écartées

Option retenue : application Next.js via OpenNext sur Cloudflare Workers pour l'alpha, Neon Free pour PostgreSQL et Neon Auth, Cloudflare R2 pour les fichiers. Le développement local utilise PostgreSQL et les mêmes migrations SQL.

4. Coût et seuils d'exploitation

Développement

0 USD/mois. Exécution locale et ressources gratuites partagées.

Première alpha

0 USD/mois. Limites bloquantes, démarrage à froid et restauration courte acceptés.

Passage au payant

Seulement après dépassement mesuré, données devenues irremplaçables, revenu ou exigence de continuité.

Conséquence : 0 USD signifie des quotas, pas une capacité illimitée. Les métriques, exports et essais de reprise doivent précéder l'augmentation d'un plafond.

5. Portabilité et stratégie de sortie

  • Application : Next.js standard, cible Docker et tests hors runtime Cloudflare.
  • Données : SQL PostgreSQL versionné, sauvegarde logique et restauration testée.
  • Identité : compatibilité Better Auth et UUID métier indépendant du fournisseur.
  • Fichiers : API S3 et inventaire exportable des objets.
  • Jobs : outbox métier indépendante du transport de messages.

6. Critères d'acceptation

  1. Le premier parcours peut fonctionner à coût fixe nul dans les plafonds documentés.
  2. Les frontières application, données, identité, fichiers et jobs ont chacune un propriétaire clair.
  3. Les données privées sont protégées côté serveur et en base, jamais seulement par l'interface.
  4. Les migrations SQL et les adaptateurs rendent un changement de fournisseur réalisable.
  5. La production ne reçoit aucune migration non vérifiée sur development.
  6. La CI est introduite avec du code exécutable et ne remplace pas la revue humaine.
