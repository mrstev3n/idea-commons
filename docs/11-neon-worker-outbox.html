IC-07 — frontière runtime Cloudflare

Statut : spécification locale, cible dev. PR #7 intégrée dans dev au SHA 6c322978. Aucune validation distante de ce lot n’est encore acquise.

Contexte

PGlite persistant, le sous-processus Node et la consommation opportuniste de l’outbox depuis GET sont incompatibles avec Cloudflare Workers. Neon Data API est active sur development et constitue la frontière membre normative.

Objectif

Servir les actions membre via PostgREST/Data API et JWT Neon Auth, exécuter l’adaptateur simulé sans spawn, et relayer l’outbox par Cron + Queue avec lots et retries bornés.

Non-objectifs

Les routes Auth et l’interface identité appartiennent au lot Auth. Aucun appel IA réel, domaine personnalisé, service payant, déploiement production ou credential propriétaire n’est introduit.

Principes

  • Membre : NEON_DATA_API_URL, JWT serveur, profil app, RPC métier étroites. Aucune URL authenticated@, aucun SQL arbitraire, aucun accès direct aux tables.
  • Identité : runtime_identity() renvoie {authUserId, memberId, roles}; le runtime compare strictement authUserId à la session et n’accepte que contributor/reviewer/admin.
  • Continuation : ic_trusted_continuation n’exécute que record_verified_source_fingerprint via un secret serveur distinct.
  • Outbox : ic_runtime_service passe uniquement par OUTBOX_DATABASE/Hyperdrive. Cron prend au plus 5 leases; Queue consomme à concurrence 1, avec backoff 15–900 s, cinq retries et DLQ.
  • HTTP : GET ne produit aucun effet outbox. Le consommateur est idempotent; un crash après envoi peut rejouer le même identifiant durable.

Surfaces Data API exposées

Schéma app; fonctions seulement : runtime_identity, runtime_source_by_fingerprint, runtime_source_to_idea_skill_version, runtime_publication_receipt, runtime_list_published_ideas, runtime_get_published_idea, runtime_list_editorial_cases, runtime_get_editorial_case et les cinq commandes métier M1 déjà définies. La migration révoque tous les privilèges de tables app à anonymous/authenticated.

Critères d’acceptation

  1. Typecheck indépendant des artefacts .next/dist; builds Next et vinext reproductibles.
  2. Tests exécutables du JWT/RPC mock, relay/lease, crash après send, doublon, ack/retry/backoff, épuisement/DLQ et composition fetch/scheduled/queue.
  3. Audit fail-closed des attributs, memberships, tables, séquences et fonctions des identités service.
  4. Readiness distante refusée tant que JWT/RLS positif+négatif, deux rôles minimaux et bindings Cloudflare ne sont pas prouvés.

Preuve distante suivante

Après contre-revue : appliquer 0006, exposer uniquement app, rafraîchir le cache PostgREST, prouver JWT A et témoin B/anonyme, auditer les deux rôles, configurer le secret de continuation, puis vérifier Queue/DLQ/Hyperdrive/Cron sur preview. Le fichier runtime-readiness.json reste faux jusque-là.
